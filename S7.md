# Offline S7 DB adapter

The adapter translates between compiler-owned Wasm state and classic S7-300/400
DB images. It does not open sockets, connect to PLCSIM or change WinCC settings.
The Wasm ABI stays at version 1. The native runtime gains a generic codec; each
project supplies a generated local map instead of project-specific native code.

## Generating the map

Use `compile_program.py --s7-map` with the normal build options and `--runtime`.
The resulting `s7-map.json` stays beside the package in ignored `build/` storage.
It is protected project data and must never be committed or uploaded.

DB numbers come from the STEP 7 symbol table. Field offsets are calculated from
parsed declarations, independently of internal Wasm offsets. The generator then
checks every entry in both exported DSP address tables against the calculated
DB number, bit address and scalar type. An unknown address, missing table or
type mismatch fails generation. Equipment tag names become aliases for the
underlying indexed SCL field paths. Aliases are not assumed to equal field names.
STRING capacity comes from its declaration; legacy table type columns may be
truncated and do not independently establish that capacity.

The map covers reachable, allocated DBs. It does not allocate unused DBs or map
I/Q/M process-image symbols. Exported tags referring to an unallocated DB cause
generation to fail. All mapped fields default to read-only. Only exact field
addresses found in the exported write table become writable. Source tables are
never edited. Existing generated maps are removed before regeneration so a failed
build cannot leave an apparently current map behind.

Each map is bound to the packaged Wasm SHA-256 and persistent output region.
Loading validates DB ranges, type widths, alignment, duplicate names and both
external/internal field overlap. The map file limit is 64 MiB, DB image total is
16 MiB, an individual DB is limited to 65,536 bytes, and at most one million
scalar fields are accepted. These are adapter limits, not CPU-specific capability
claims. Hash binding detects accidental package mismatch; it is not a signature
or a substitute for trusting and reviewing generated configuration.

## Representation

- BOOL values occupy individual S7 bits and full internal 32-bit slots.
- BYTE, WORD/INT and DWORD/DINT/REAL use their S7 widths and big-endian ordering.
- INT reads sign-extend into internal slots. REAL preserves finite binary32 bits.
- STRING has a capacity byte, length byte and payload; its size is word padded.
  Character bytes are preserved, without transcoding.
- Structures start and end on word boundaries. Arrays are row-major with declared
  lower bounds; BOOL rows end on byte boundaries. Padding is zero in published
  snapshots and cannot be written. Unsupported compiler types remain rejected.

The layout rules follow Siemens
[S7-SCL V5.3, chapter 7](https://cache.industry.siemens.com/dl/files/793/5581793/att_66783/v1/SCL_e.pdf).
Exported address-table agreement and codec tests do not replace comparison with
compiled STEP 7 DB offsets or the live reference PLC, especially for fields not
present in those exports.

## Runtime API and publication boundary

`station_runtime::s7::Bridge` exclusively owns a Runtime and its validated Map.
`read_db`, `read_bit` and `read_named` return owned values from the last published
generation. Names can be full field paths or exported aliases, case-insensitively.
Ambiguous aliases are rejected; the full field path remains available. Named
reads/writes use S7 byte representation; BOOL uses a single canonical 0/1 byte.

`queue_bytes`, `queue_bit` and `queue_named` stage requests without changing the
published snapshot. Requests are applied in order to a pending DB image. Later
writes to the same location win. Each request is atomic: bounds, access and value
validation complete before it replaces pending state. A rejected request leaves
earlier accepted requests intact. `discard_pending` cancels the pending batch.
Partial byte writes are supported. A byte request may preserve read-only bits
sharing a byte, but cannot change them. Writes exclusively targeting read-only
data or padding are rejected. Invalid STRING headers and non-finite REAL values
are rejected before reaching Wasm.

At `cycle`, changed writable fields are decoded into internal state before scan
execution. On success, every DB image is rebuilt and published together, and the
generation counter advances. Admission to the queue does not acknowledge scan
completion, and the program may consume or overwrite a written value during that
scan. Invalid cycle arguments preserve the queue for retry. A Wasm fault or an
invalid encoded output latches the bridge fault, discards publication and requires
reload. Reads then retain the last successful generation; adapters must expose the
fault as bad/stale quality rather than present it as fresh data.

Network workers must not hold Wasm pointers or mutate these DB images directly.
A future Snap7 server must pass writes through this queue and serve consistent
owned snapshots. This adapter does not implement Snap7 callbacks, OPC UA, command
acknowledgement across reconnects, persistent recovery or multi-request atomic
transactions beyond the pending batch consumed by one cycle.

## Offline replay

`station-runtime s7-run PROGRAM.pkg MAP.json ACTIONS.json` loads and validates the
pair without networking. The local actions file is a JSON array with an `op`:

| Operation | Arguments |
| --- | --- |
| `read` | `db`, `offset`, `length` |
| `read_named` | `name` |
| `write` | `db`, `offset`, `data` byte array |
| `write_named` | `name`, `data` byte array |
| `write_bit` | `db`, `byte`, `bit`, `value` boolean |
| `cycle` | `elapsed_ms` |

Read results include the published generation and byte array. Invalid actions
fail the replay. This command uses zero-filled ABI inputs and is an offline test
interface, not a network service or a wall-clock scheduler. Project actions and
results must remain in ignored local directories.

## Resource monitoring

`station-runtime monitor PROGRAM.pkg MAP.json [PERIOD_MS] [CYCLES]` keeps the
complete offline program and S7 bridge resident for process-resource inspection.
Defaults are 100 ms and unlimited cycles; a nonzero cycle limit allows finite
checks. Use a release build for representative measurements. JSON lines on stdout
report load time, Wasm/state sizes, first scan and ten-second windows of scan plus
DB conversion duration and missed deadlines. OS resident/private memory and CPU
must be measured separately; Wasm linear memory is only part of process usage.

This mode has zero-filled ABI inputs and no device or WinCC connection. It sleeps
between deadlines and skips missed deadlines without catch-up bursts. It passes
the configured interval to the ABI; source programs maintaining their own time
constants still use those constants. It provides no hard real-time guarantee.
On fault it exits with a diagnostic. Stop an unlimited run by terminating its
process. Keep project-specific logs and launch settings in ignored local storage.
